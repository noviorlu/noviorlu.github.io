## 它解决什么问题

读一个上千个文件的推理框架，最难的往往不是某个函数，而是**全局**：模块之间谁依赖谁、一个请求进来到底走了哪条路、哪些 import 只是摆设。codestrata 把这件事拆成两张共用坐标的图：

- **总图（静态）**：用 AST 扫全仓，画出模块级的依赖。层次不是手工标的，而是由 import 的出入度算出的「架构高度」——入口在上，纯被依赖的叶子在下。
- **运行图（runtime）**：跑一个真实的 case（仓库自带的 example，或者起服务、发一次请求），把实际发生的跨模块调用叠在**同一张图、同一套坐标**上。这个 case 走了哪条路，一眼可见。

## 图上的线

| 线 | 含义 |
|---|---|
| 灰实线 | import 了，而且代码里真的引用了对方的符号 |
| 灰虚线 | 只 import、一个符号都没引用（死 import、re-export、只给类型检查、为了副作用……） |
| 橙色 | 这次运行真的跨这条边调用过，粗细 ∝ log(次数) |
| 橙虚线 | 只在运行时出现、静态 import 图里没有——插件、`importlib`、注册表这类静态分析的盲区 |

选中用蓝色光晕表示，不改边本身的颜色：选中一个模块时，最想看的恰恰是它的边里哪些是真调用。

## 点开之后能看什么

- **点边**：这条依赖具体承载了哪些函数 / 类、在哪一行、这次运行里被谁调了几次。
- **点节点**：模块的规模、依赖与被依赖、这次运行里调用最多的符号，以及给它写的解读。目录节点可以原地展开。
- **看代码**：源码按扫描时的提交号从 GitHub 实时取回、在浏览器里高亮；Ctrl+点击跳到定义，并列出全仓的引用。
- **换运行**：页面上方可以在静态图和每一次录制之间切换；分了阶段的运行（启动 / 服务 / 关闭）还能只看其中一段。

## 这些页面是怎么来的

每个查看器都是 `codestrata graph --link github --public` 导出的纯静态网页：图、解读和运行数据随页面带上；源码不随页面分发，而是按提交号从 GitHub（jsDelivr，不行再 raw.githubusercontent.com）取，所以行号永远对得上扫描时的代码。公开导出会把本机路径写成 `~`，并省略和仓库无关的环境信息。
